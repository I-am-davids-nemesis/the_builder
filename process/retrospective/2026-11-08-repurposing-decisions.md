# Repurposing: what the writer decided

_Written by Claude on November 8, 2026. It follows up on `2026-11-08-why-rotating-third.md`, whose four questions about retelling the book from other viewpoints and as a screenplay the writer answered the same day. This file records the answers. Retrospectives can't change the files the decisions belong in, so the last section lists where each one should go._

## The decisions

1. **Repurposing is a later project, not a rule for this draft.** The writer chose the option to keep it in `ideas.md` rather than add it to the book's form in `engine.md`. The draft is written for readers of this book. Other viewpoints and a screenplay come later.
2. **No blanket rule for visual insight; questions instead.** The writer thought a rule that every viewpoint insight needs something a camera could see "might make for an interesting constraint," but preferred to "ask questions about each of those issues so we can resolve them as they come up." Alongside that: "We can keep a list of flags in process about things that might be difficult to render visually."
3. **The camera branch stays as it is.** "We may come back to the different POV issues later; it isn't clear if this will help the screenplay generation or not yet." It isn't an archive or a resource for now, just kept.
4. **Characters get a "where they break pattern" line.** The writer took the default: when each main character's profile is next revised, it gains a short line on where they're allowed to surprise. That answers the writer's "sufficient (but not too much) consistency."

## What this says about how the book is made

The answers repeat a pattern the meta-story found. The writer is wary of rules made in advance and prefers to decide case by case, with a record. Parallel drafting (October 9) put off choosing a mode until the drafts could show the answer. The camera files were moved to a branch rather than deleted. The question format (October 31) turned open issues into small decisions, one at a time. Here, too, the screenplay goal stays open: there's a list to watch, not a constraint on the prose.

The cost is small but real. A flag list only works if sessions remember to add to it. Since the panel starts a fresh conversation for each scene, the practice has to be written down where every session reads it.

## Where each decision should be recorded

A normal panel session (not a retrospective) can make these changes:

- **`process/ideas.md`:** a dated entry (November 8, from the why-rotating-third retrospective) for retelling the book from other viewpoints and adapting it as a screenplay, with sketched storyboards rather than photorealistic images.
- **A flags file in `process/`**, for example `process/visual-flags.md`: one line per thing that might be hard to render visually, with the scene, what the page does, and why a camera can't, plus the answer once there is one. Both the name and the format are suggestions.
- **`AGENTS.md` §10:** a line telling agents that when a scene puts something on the page that only narration can carry, they ask about it in the outline's questions and add it to the flags file. Without this, the practice won't survive fresh panel conversations.
- **`codex/README.md` template and each main profile:** a "Where they break pattern" field, added when each profile is next revised, not all at once.
- **`journal.md`:** a Claude entry for the day, covering the beta reader as the reason rotating third won, the seed in the writer's words, and these four decisions, pointing back to the October 27 entry.
